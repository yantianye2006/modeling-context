# 数学建模设计与交接门禁

## 题面与子问题

- 二次核对 PDF、扫描件、公式、上下标、单位和表格字段。
- 只把题面明确编号的顶层问题识别为子问题。
- 每问明确输入、输出、变量、目标、约束、评价标准和上下游依赖。
- 对关键歧义列出至少两种解释，用单位、简单验算和题目递进性选择当前解释。
- 后续问题新增资源或放宽约束时，目标通常应按预期方向改善；否则检查解释、约束方向和求解质量。

## 目标可估性与数据支撑审计

在选择模型前先完成分析卡中的 G0 审计；G0 通过后按 `model-diagnostics.md` 完成 G0.5，模型设计只能在已通过路线的获准范围内展开。同时区分：

- 结构可识别性：理论观测是否能唯一确定模型参数；
- 数据支撑：现有样本是否包含足够的独立信息；
- 决策分辨率：数据是否足以支持题目要求的点估计、排序或精细方案。

按“数据行数 → 独立个体或单元数 → 支撑目标量的事件、区间、少数类或有效对比数”记录信息坍缩链，并说明重复测量、组内相关及时空依赖怎样减少独立信息。事件数、少数类数量和 ICC 等只作为证据，不使用跨题型固定阈值。

判定为“支撑偏弱”或“当前不支撑”时，选择并登记一种或多种处置：更换目标量；降为辅助或探索模型；改为区间、场景或部分识别结论；保留题目要求的必要主模型，但降低复杂度、扩大不确定性并禁止无证据的高精度点结论。

完成审计且交付物分辨率与处置一致时，G0 可以通过；审计未完成，或数据只支持粗粒度判断却仍计划输出精细最优点时，G0 必须阻塞。

示例：1082 条检测记录可能只对应 267 个独立个体，其中仅 43 个个体提供目标事件区间。这个事实可支持“数据支撑偏弱”的判定和降级处置，但不能外推成其他题型的固定样本阈值。

## 模型表达

关键假设必须必要、可解释、可参数化，并登记理由、影响范围、风险和验证方式。物理和业务约束优先于计算方便。

每个主模型至少提供：

1. 符号、变量类型、单位和定义域；
2. 数学表达、目标函数和完整约束；
3. 输入、输出和所需数据预处理；
4. 求解核心步骤、停止条件和规模可行性；
5. 评价指标、基线或对照、验证划分；
6. 敏感性因素、参数范围和稳健判据；
7. 适用边界、外推限制和失败场景。

公式必须清楚到实现阶段无需猜测口径。启发式算法不得宣称全局最优，除非有证明、精确求解对照或可信的稳定性证据。

## 参数来源与决策敏感性

在分析卡 §11.1 登记承载模型、目标函数、约束和最终推荐的参数。区分题面、可靠文献、数据估计、校准和自定来源，并说明不确定性依据。优先扰动“来源较弱且最终答案敏感”的参数；自定参数通常风险较高，但不机械压过所有估计参数。

目标函数或约束包含分段、绝对值、`min/max`、取整、指示函数、时间窗、容量边界或阶梯价格时，检查最优解或推荐点是否落在断点、边界或离散角点。若答案依附于外生或自定断点，移动断点重跑，分别说明哪些结论由数据支持、哪些由规则设定产生。

承载最终答案的高敏感参数必须登记扰动范围和证据。不存在需要登记的参数，或模型没有上述角点结构时，可以把相应自检记为 `not-applicable` 并写明理由；不得把“尚未检查”写成“不适用”。任一高敏感参数未扰动，或角点检查仍为 `not-checked` 时，G3 不得通过。

## 题型防错

### 优化、调度、选址、路径

- 明确 min/max、连续/整数/二元变量、非负、上下界、容量、预算、时间窗和前驱约束。
- 先构造并验证可行解，再优化目标值。
- 连续松弛后说明取整和可行性修复。
- 非凸或启发式求解使用多起点或多随机种子；TSP/VRP 检查子回路。

### 多目标与评价

- 先统一指标方向并无量纲化，再加权或进行 Pareto 分析。
- 说明权重来源和各目标贡献，不能直接相加不同量纲的成本、时间和风险。
- AHP 检查一致性；TOPSIS、熵权、DEA 等说明标准化与排名敏感性。

### 预测、统计与机器学习

- 时序数据按时间划分，禁止未来信息泄露。
- 标准化只在训练集拟合，再用于验证/测试集。
- 检查残差、共线性、异常值、类别不平衡、外推范围和物理边界。
- 不在测试集调参；记录交叉验证、超参数范围和误差评估。

### 动力学、仿真与微分方程

- 写清状态变量单位、初始条件、边界条件和守恒关系。
- 说明求解器、步长或网格，检查刚性、漂移和收敛性。
- 接触、饱和、反弹等机制不能因计算方便而删除。

### 图论、网络与空间布局

- 明确有向/无向、权重、容量、连通性和流量守恒；负权边不用 Dijkstra。
- 有尺寸的实体不能无依据降维为中心点。
- 旋转矩形优先使用 OBB/SAT；统一坐标系和角度单位。

## 主模型与辅助模型

主模型负责直接回答题目。辅助模型只承担以下一种或多种职责：机理解释、非线性检查、因素排序对照、替代口径或独立验证。

G0.5 通过前两者都只可作为条件候选，不得冻结。不要从“表格数据适合 boosting”等算法经验直接推出主模型；同一算法跨问重复本身也不构成缺陷，逐问证据才决定是否采用。

两个模型结论不一致时，记录：

- 冲突发生在哪个指标或范围；
- 哪个模型更符合题面目标、约束和验证证据；
- 最终采用哪个模型以及另一个模型的保留角色；
- 是否影响下游问题和已有结果。

## 实现交接

向编程阶段交付当前问题的以下接口：

| 项目 | 必须明确的内容 |
| --- | --- |
| 输入 | 文件、字段、单位、范围、上游结果 |
| 输出 | 数值、表格、图表数据、下游接口 |
| 方法 | 数学公式、算法步骤、参数、随机种子 |
| 校验 | 约束、误差、基线、稳健性、边界测试 |
| 记录 | 中间数据、参数、迭代历史、运行日志和证据路径 |

实现阶段逐问题运行和验证，不一次性写完后再检查。数据驱动图表应保存生成数据和记录；流程图、架构图和论文排版不属于此阶段。

## 具体实验与方案门禁

模型提出的实验点、最优参数、调度或资源配置只有在可行域被确认后才能写成可执行方案。至少确认变量类型、上下界、离散水平、制造/执行精度、物理与安全约束、预算与时间约束、一次实验或一次决策的定义，以及是否允许重复、对照和序贯更新。

如果题目或附件没有给全这些信息，先输出实验角色、选择准则、候选区域和需要用户确认的问题。不要用默认范围或模型极值补出具体坐标。用户补充后再生成方案，并把补充信息和采用理由写入决策日志。

## 结果回填

结果不得只停留在终端或临时对话。登记内容、数值权威、状态推进和下游影响全部执行 `pipeline.md` §10「回填结果并闭环」，本文件不另列一份。
