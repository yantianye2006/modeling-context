# G0.5 结构诊断与建模路线门

## 1. 职责与红线

G0 回答“能不能建模”，G0.5 回答“应沿哪类结构路线建模”，G1 回答“路线确定后具体怎样建模”。严格执行以下五条：

1. G0.5 通过前，G1 只能记录条件候选，不得冻结主模型。
2. G0.5 为 `not-checked` 时，本问模型状态不得为 `主模型`，G1 不得为 `passed`。
3. G0.5 转为 `passed` 前，诊断结果完整、权威产物真实存在、判据预登记早于运行开始且哈希一致三项必须同时满足。
4. 判定 `information_limited` 前必须完成 E1–E4；四项全部为“否”才可通过。
5. 不以模型在多问中重复作为否决理由；只检查每问是否有独立证据，或是否如实登记共享证据。

除这五条外，探针实现、阈值、重复次数、记录细节和题型模块都按题目与预算调整。调整时仍须在观察结果前声明判断规则，并完整报告不利证据。

## 2. 公共骨架与预测类模块

所有题型共用五件事：决策契约、竞争性结构假设、平凡基线对照、预先声明判据、路线与否决。当前版本只实现预测类诊断；优化、机理、仿真或评价题沿用公共骨架，但不得机械套用交叉验证、折内差异或分类指标。

### 2.1 决策契约

在探针运行前明确目标或待解释对象、样本单位、官方主指标、实际用途、预测/决策时点、当时可得字段、合法划分和防泄漏要求。用途未知就写“未明确”，不得虚构部署场景。

### 2.2 竞争性结构假设

预测类任务通常提出至少两个可由实验区分的解释，并优先纳入简单解释或空假设；题面结构唯一、样本极小或预算不足时可减少，但须登记理由、未比较路线和误判风险。

- H0：当前字段不存在超越平凡基线的稳定信号。
- H1：信号主要是低阶、近似线性或单调结构。
- H2：存在稳定非线性或变量交互。
- H3：存在顺序、层级、时序、机理或守恒等题目特有结构。
- H4：总体能力有限，但局部子群、极端样本或特定决策区间仍有价值。
- H5：目标参与某个可观测变量的生成过程，正向判别拟合可能弱于生成方向拟合后反演。

H5 被提出时独立成条，不并入 H3；但不要在没有生成机制线索时机械填写 H5。

### 2.3 最小诊断探针

从以下角色选择能够区分假设的最小充分组合：

- 平凡基线：多数类、均值、简单规则或题面现成方案。
- 低容量探针：线性、广义线性或其他简单可解释模型。
- 通用非线性探针：一种成本可控的树、核或小型神经网络。
- 结构专用探针：仅在存在明确结构假设时加入。
- 反演探针：仅在 H5 被提出且识别条件允许时加入；与直接条件化同一观测变量的判别式探针共享划分，用二者差异识别拟合方向的贡献。

算法名称只说明实现，不赋予主模型地位。

### 2.4 预先声明的判据

观察结果前逐题声明主指标、辅助指标及优先级、指标冲突的取舍、最小有意义增益、最差情形退化容忍、训练—验证差距、复杂度升级条件和停止条件。存在折、种子、实例或场景等配对重复单元时报告方向一致性；“过半”只可作预测类默认参考，不是单项硬否决线。

单个指标不理想通常是不利证据或复核提示。只有该题预登记为硬条件，或触碰本文件五条红线时，才由单项直接否决。最终裁决偏离预登记默认规则时，在决策日志追加理由、证据、风险和下游影响，不回写原判据。

## 3. 两层诊断执行

### 3.1 A 层：结构探路

使用合法且成本可控的共享划分；各探针只用少量预先固定的代表参数，不大规模调参。比较基线、简单结构、非线性结构、训练—验证差距和明显的稳定性风险。

A 层是本问 M1 的前置项，不得因“M1 未完成时暂停 M2/M3”而推迟。它是 `stage: analysis` 内的受限诊断执行例外：允许编写并运行只服务于结构诊断的代码，产物只能进入 `<project-root>/outputs/diagnostics/` 或 `<project-root>/outputs/pilot/`。不得读取锁定测试指标、冻结主模型、开展正式大规模调参或把诊断产物冒充最终交付。

### 3.2 B 层：路线确认

准备让复杂路线晋级、A 层差异不确定，或需要对高影响路线形成强否决时，再选择多随机种子重复验证、配对差异、胜出重复、区间、最差情形、泛化差距、计算成本和解释成本。重复次数与统计形式由样本依赖结构、时间和决策风险决定，不设统一规格。

## 4. 证据解释与路线

G0.5 只输出结构路线和获准范围，不输出最终超参数：

- `simple`：简单统计或线性路线。
- `nonlinear`：通用非线性路线。
- `structured`：结构专用路线。
- `information_limited`：信息不足，保留基线并形成负结论。

重构与路线分开记录：`reformulation: none | target | information | output`。重构尚未验证时保持 `not-checked`；验证后同时填写重构动作和重构后的路线。人读摘要可以写“R5 重构信息组织”，机器记录写 `reformulation: information` 与实际 `route`。

默认解释如下，但不能替代逐题预登记：

| 观察 | 默认处理 |
| --- | --- |
| 简单与非线性都贴近平凡基线 | 进入信息不足诊断，不增加容量，不直接判 `information_limited` |
| 两者相当且简单模型更稳定 | 通常支持 `simple` |
| 非线性在关键指标上稳定胜出 | 通常支持 `nonlinear` |
| 通用模型一般，结构专用探针稳定提升 | 通常支持 `structured` |
| 平均略升但区间跨零、方向不稳或最差情形恶化 | 默认保留较简单路线，再按预登记优先级综合裁决 |
| 官方指标弱，但预登记且题意支持的排序、筛选或分层用途有效 | 可重构 `output`，但不得声称原目标已解决 |
| 结果对划分高度敏感 | 保持 `not-checked`，补稳定性诊断 |

结论还须记录核心证据、多指标取舍、偏离预登记规则的理由、已否决路线、适用边界、G1 获准范围与重新开启条件。

## 5. 信息穷尽审计

当探针均贴近平凡基线时，逐项回答：

- E1：输入边界内是否还有未纳入且在预测时点可得的字段，包括其他任务目标列或上游折外预测？
- E2：是否存在单变量扫描和轴对齐分裂难以还原的显式构造量，如比值、差值或守恒式？
- E3：是否存在未利用的分组、层级或时空结构？
- E4：目标是否参与某个可观测变量的生成过程，因而值得检验反演方向？

发现可能通道时先记 `候选`，保持 `not-checked`，预登记针对性检验。检验支持后转为相应重构或结构路线；不支持时记“否”并保留否决证据。E1 与 E4 都必须说明预测时点可得性，不得引入当前任务真值或其确定性派生量。只有 E1–E4 全部为“否”时，才可通过 `information_limited`。

失败原因诊断从标签排列、学习曲线、子群扫描、显式构造量、标签噪声、字段遗漏和可恢复性能空间中选择最小充分组合，不要求全部执行。

## 6. 状态、预登记与 manifest

### 6.1 gate 字段

G0.5 使用：

```yaml
status: not-checked | passed | blocked
route: null | simple | nonlinear | structured | information_limited
reformulation: null | none | target | information | output
diagnosis_version: null | <稳定版本 ID>
```

`route`、`reformulation` 和 `diagnosis_version` 只在 `passed` 时有值。普通不确定性用 `not-checked`，只有缺失数据、定义或外部条件才用 `blocked`。`not-checked` 不填写 gate 的日期、阻塞、豁免或证据。

G1 通过时填写 `unlocked_by`，其值必须等于当前 G0.5 的 `diagnosis_version`。这使路线失效后无法沿用旧 G1。

### 6.2 探针状态

第 3 节“最小诊断探针”的状态只用：

- `planned`：适用但尚未执行；G0.5 不得通过。
- `executed`：已经执行，必须在第 5 节有完整结果。
- `not-applicable`：不执行，必须写明理由与误判风险。

### 6.3 判据哈希

填写第 4 节时运行：

```powershell
python "<skill-dir>/scripts/hash_g0_5_criteria.py" --context "<project-root>/modeling" --question <N>
```

把输出哈希同时写入分析卡与决策日志的 G0.5 判据预登记条目。规范化输入由适用探针的稳定字段和第 4 节判断标准构成；探针的 `planned/executed` 变化不改变哈希，改为 `not-applicable` 会改变哈希。不得手工拼接另一套哈希口径。

预登记条目至少包含带时区秒级时间 `registered_at`、`criteria_hash`、提出来源、尚未观察结果的声明、完整判据和 `状态: proposed`。结果回填时只追加裁决，不改写该条目。

### 6.4 run manifest

每个结果行引用一个位于 `outputs/` 下的 JSON manifest。路径相对项目根目录填写为 `outputs/...`。manifest 至少包含：

```json
{
  "run_started_at": "2026-08-07T14:30:00+08:00",
  "criteria_hash": "sha256:<64 hex>",
  "split_id": "<稳定划分标识>",
  "probe_ids": ["P0", "P1"],
  "artifact": "outputs/diagnostics/q1/results.csv"
}
```

`registered_at` 必须早于 `run_started_at`；二者都使用带时区秒级时间。操作系统 mtime、同日日期或事后 README 不能作为时序证据。结果表的权威产物与 manifest 必须真实存在；manifest 中的哈希、探针 ID 和产物路径必须与分析卡一致。

## 7. 跨问题证据复用

每个结果行填写稳定 `evidence_id`。两问复用同一 `evidence_id`，或复用相同产物行与指标值时，必须在两问分别填写共享生成机制、本问适用理由和反例风险。未分别登记则报错。

相同算法、相同路线或相似文字只触发人工复核，不自动否决。检查对象是证据是否被冒充为独立生成，不是算法名称。

## 8. 失效与回滚

目标或样本单位、预测/决策时点、可得字段或泄漏边界、数据划分、主指标及方向、预登记判据、核心权威产物或已通过路线发生实质变化时：

1. 将 G0.5 置回 `not-checked`，清空 route、reformulation 和当前 diagnosis_version；旧版本与理由保留在决策日志。
2. 将 G1 置为 `blocked` 并清空 `unlocked_by`，问题退回 `stage: analysis`。
3. 原主模型退回 `候选`，不删除历史决定与证据。
4. 逐条把受影响正式结果、交付物和下游结论标为失效或 `superseded`，列出重跑项。
5. 新诊断通过后生成新 diagnosis_version，再重新执行 G1。

纯措辞修正、路径重命名或不改变数据与裁决含义的补充说明通常不触发回滚，但要记录判断理由。
