# 输入读取、上下文路由与临时文件规则

## 1. 先判断任务，再读取文件

用户指定文件、问题、章节或阶段时，严格以指定范围为起点。根据 `depends_on`、`feeds_into`、`question`、`stage`、`status` 和正文链接，只补读完成任务所必需的直接依赖。

每轮开始时简要说明：

```text
本轮指定读取：问题2_分析卡.md
自动补读：02_统一口径.md、03_假设与风险.md#H01
补读原因：问题2直接依赖统一口径，且引用H01
未读取：问题3、问题4、过期决策和无关结果
```

不要为了“了解全局”默认通读整个 vault。只有全局一致性检查、项目收敛或用户明确要求时才扩大范围。

## 2. 题面理解门禁

数学建模题面通常为PDF。以只读方式提取文字并核对版面，至少确认：

- 题目名称、核心目标和明确编号的顶层问题；
- 关键公式、上下标、单位、表格和名词解释；
- 附件清单及每个附件对应的问题；
- 输出要求、严格/非严格边界和实验限制。

出现以下任一情况时停止，不初始化错误数量的问题卡，也不继续模型选择：

- 无法确认顶层问题数量或编号层级；
- 关键公式、上下标、单位或边界无法辨认；
- 题面术语存在会改变模型方向的歧义，且无法由逻辑和附件解决；
- PDF内容缺页、损坏、加密或抽取结果与视觉版面冲突。

向用户指出具体页码、公式、术语或冲突，并请求解释或更清晰的原件。得到答复后把用户说明登记为证据，再继续。

## 3. Excel只读解析门禁

对 `.xlsx`、`.xls`、`.csv` 或 `.tsv` 调用可用的 spreadsheet 解析能力。不得用猜测代替解析。至少检查：

1. 文件是否能打开、工作表名称与数量；
2. 每表有效区域、标题行、多级表头、合并单元格和公式；
3. 字段名、单位、数据类型、缺失、重复和异常；
4. 题面声明的记录数、分组和计算关系是否与附件一致；
5. 至少一次只读视觉检查，确认表头和布局解释没有错位。

原始Excel始终只读。清洗数据、字段映射和解析结果另存到后续阶段的输出目录；不得覆盖原件。

解析失败时报告：文件名、工作表、范围或字段、所用解析能力、原始错误和已经尝试的只读检查。请求用户提供可读副本、CSV导出或字段说明后暂停相关分析。

若视觉渲染失败或出现黑底、错色、裁切，但值、公式和表头已经通过其他只读方式核实，记录“视觉预览受限”后可以继续数据分析。不要修改原工作簿以修复预览。

## 4. 可行域门禁

在给出具体实验点、最优工艺参数或可执行方案前，按 `modeling-guardrails.md`「具体实验与方案门禁」确认可行域，本文件不另列一份清单。

与输入读取直接相关的一条：题面或附件没有给全可行域信息时，先在此登记"哪一项缺失、缺在哪个文件或表格"，再按该节向用户提问；不要生成看似精确但不可执行的具体坐标。

## 5. 临时文件

所有PDF页面图、Excel预览图、文本抽取、检查脚本、运行日志、缓存、依赖链接和一次性中间数据放入：

```text
<project-root>/tmp/
```

`tmp/` 不属于Obsidian建模知识库，不在论文、分析卡或项目总览中作为最终证据。需要长期保留的清洗数据、结果表、图表或日志应迁移到正式输出目录并建立证据链接。
