# 交付物清单

> [!context]
> 当前阶段：交付物需求定义
> 当前目标：登记题目最终要求的图、表、规则、阈值、排程与方案，并声明每项交付物支撑的结论和验收条件
> 已确认：
> 未解决：
> 禁止直接假定：分析过程中产生的临时文件就是最终交付物

本文件是交付物的**需求侧**清单，回答“最终必须交什么、为什么交、由什么证据产生、怎样才算可用”。
已经生成的文件位置属于**产物侧**，同时登记在条目的 `artifact` 字段和 [[项目设计总览]]；二者不得互相替代。
每个 `planned` 条目都应能回指对应问题分析卡 §1.1 的交付物骨架和 §1.2 的题面要求；骨架定义字段、单位、粒度和使用方式，本文件用稳定 ID 管理其生命周期。
旧项目中的 `图表清单.md` 继续受校验器兼容，但新项目只生成本文件；迁移前先运行升级预览，不静默改名或覆盖内容。

## 通用核心字段

| 字段 | 必填时机 | 含义 |
| --- | --- | --- |
| `id` | `planned` | 稳定且全项目唯一的条目 ID；建议 `D-Q2-01`，不要把 kind 写入 ID |
| `kind` | `planned` | `figure / table / rule / threshold / schedule / plan` |
| `question` | `planned` | 问题编号或 `global` |
| `status` | 始终 | `planned / drafted / active / superseded` |
| `label` | `drafted` | 交付物中的唯一引用标识或正式名称 |
| `claim` | `planned` | 本条目直接支撑或交付的一句话结论 |
| `claim_source` | `drafted` | 分析卡中该结论的稳定位置 |
| `source` | `drafted` | 输入证据或权威数据；写具体文件、字段与聚合方式 |
| `artifact` | `drafted` | 权威产物文件或可执行定义的位置；不得只写临时终端输出 |
| `acceptance` | `drafted` | 可逐项判定的验收条件；升 `active` 前全部有证据 |
| `supersedes` | `drafted` | 被本条目吸收或替代的旧条目 ID；确无则填 `[]` |

`source` 回答“依据什么”，`artifact` 回答“最终产物在哪里”，`claim_source` 回答“正文中的结论在哪里”；三者不得混写。

## kind 专属字段

| kind | `drafted` 前补齐 | `active` 前补齐 |
| --- | --- | --- |
| `figure` | `panels`、`caption` | `口径核验`、`产物回看` |
| `table` | `columns`、`units`、`precision`、`missing` | `render_review` |
| `rule` / `threshold` | `inputs`、`output`、`boundaries`、`exceptions` | `executable_check` |
| `schedule` / `plan` | `feasible_region`、`time_unit`、`conflicts` | `execution_precision` |

图类条目的 A/B/C 呈现口径见 [[02_统一口径]]；只有 `figure` 受单章成稿图数量上限约束。其他 kind 只做必要性、重复性和可执行性检查，不套用图表专属字段，也不硬设数量。

## 生命周期

| status | 含义 | 最低要求 |
| --- | --- | --- |
| `planned` | 已确认存在交付需求 | `id`、`kind`、`question`、`claim` |
| `drafted` | 已有可追溯产物 | 通用核心字段齐全，kind 专属的 drafted 字段齐全 |
| `active` | 已通过验收，可进入最终交付 | `acceptance` 有证据，kind 专属的 active 字段齐全 |
| `superseded` | 已被新条目替代或因上游变化失效 | 保留完整内容，记录替代关系和失效原因，不删除 |

状态推进只描述单条交付物的成熟度，不改变本文件 frontmatter 的文件级 `status`。

## 条目

### D-Q1-01 <条目标题>

- kind: figure
- question: 1
- status: planned
- label: <正式引用标识>
- claim: <本条目支撑或交付的一句话结论>
- claim_source: [[问题1_分析卡#14 当前结果]]
- source:
  - <权威文件> → <字段> → <聚合方式>
- artifact: <生成脚本或定义> → <权威产物路径> → <交付引用位置>
- acceptance:
  - <可判定条件> → <证据>
- supersedes: []
- panels:
  - a <展示内容> ← <数据来源>
- caption: <题注>
- 口径核验: <A 类逐项实测值>
- 产物回看: <日期> 已回看并与上一版对比；<B 类逐项结论>

## 图类交付物的两轨边界

| 轨道 | 位置 | 数量 | 是否进入交付物 |
| --- | --- | --- | --- |
| 探索图 / 调试图 | 各问题代码输出目录 | 不限 | 否；不得因“已经画好”被追认为成稿图 |
| 成稿图 | 交付物图表目录 | 受 [[02_统一口径]] 声明的单章上限约束 | 是；必须对应本文件的 `figure` 条目 |

无 `figure` 条目的图不得出现在交付物图表目录；条目未达 `active` 不得被正文引用。流程图、架构图和技术路线图同样使用 `kind: figure`，`panels` 改为登记节点与连边的依据。
